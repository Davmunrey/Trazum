**`trazum bill --git-range <range> --delivery` sets the spend recorded in a repository beside what local git shows landed in the same range.** (#825) It adds two lines at the end of the `--git-range` view and changes none above them: the commits of the range (merge commits counted and named), the pull requests git names by number, the UTC days on which a commit was committed, and the figure of the sessions inside the span divided by each. Pull requests come from local git alone, by the number in `Merge pull request #N from ...` on a merge commit or in `... (#N)` closing the subject of a squash commit, counted once per number; a pull request merged by rebase names none, so the count is a floor and the line says so, and with none named there is no per-pull-request figure and never a $0. **Only metadata is read**: the log is asked for the parents, the commit time and the subject, the subject is read for a number and dropped, and no author name, email, message, branch or hash is read out or printed, and no pull request number is printed. **The wording rule of #777 holds**: the figures are what was recorded during a window divided by counts over the same window, and the line says they are not what any commit, pull request or day cost; nothing says a change caused the spend. One flag rather than a `--by commit|pr|day`, because `--by` already cuts a bill into days, weeks and months and a row per commit or pull request would be a figure for one change, which the transcripts cannot give. `--delivery` without `--git-range` is refused by name. **Without the flag the output is unchanged**, held byte for byte by `bill-git-delivery.test.js` against a statement written by hand, and checked once more by running the CLI built from `origin/main` and this one on one made-up repository: stdout, stderr and exit code identical in 10 runs (five invocations, both languages). Documented in `docs/commands.md`, under `bill`; help and messages in English and Spanish; the machine-readable output is not touched, so `docs/json-output.md` has nothing to add. Tests are in `packages/cli/test/bill-git-delivery.test.js`, on made-up repositories in temporary directories, with the money worked out by hand ($2 per million input tokens on Claude Sonnet 5.5: $4.00 over 8 commits, 2 pull requests and 2 days). Planted one at a time and put back, each caught by the test named: the author name asked of git (`asks git for the parents, the commit time and the subject, and nothing else`) or printed (`names no author, message, branch, hash or pull request number`), a line saying a commit cost the amount or caused it, in English and in Spanish (`says what the figures are, and that none of them is what a commit cost`), the delivery lines printed without the flag (`adds lines and changes none...`, `prints, without the flag, exactly what it printed before the flag existed`), a pull request counted once per commit (`reads a pull request number from the two shapes GitHub writes, and only those`), a number read from the middle of a subject (the same test), the merge shape read on a one-parent commit (the same test), a zero count divided to $0 (`names no figure per pull request when none is named...`, `divides, and gives no figure where the count is zero`), days cut by author time (`counts a day by when the commit landed, not when it was written`) and `--delivery` accepted without `--git-range` (`is refused without --git-range, by name`). The results are recorded on the pull request. Not measured: how long the second `git log` takes on a very large range.
