# Local HTTP API

[Documentation index](README.md) · [Setup](setup.md) · [JSON contracts](json-output.md#the-cost-answer-document) · [Gateway](gateway.md)

`trazum serve` exposes read-only cost and savings analysis on **127.0.0.1**, or a Unix socket.
It estimates a proposed call against the configured budget and scoped limits. It
does not invoke a model, reserve money, update spending, or enforce a provider
request. Use the [gateway](gateway.md) when the decision must sit in the call path.

## Start and discover

```sh
npx @trazum/cli serve --port 7317
curl http://127.0.0.1:7317/health
curl http://127.0.0.1:7317/openapi.json
curl http://127.0.0.1:7317/capabilities
```

`GET /openapi.json` returns the OpenAPI 3.1 contract generated by the same CLI
package. Its default server URL uses port 7317; replace the port when starting
with `--port`. The Unix-socket transport exposes the same paths.

| Endpoint | Result |
|---|---|
| `GET /health` | `200`, `{ "ok": true, "schemaVersion": 1 }` |
| `GET /openapi.json` | `200`, the complete OpenAPI contract |
| `GET /capabilities` | `200`, static harness import and access-channel metadata |
| `POST /savings/plan` | `200`, ranked savings plan with coverage evidence |
| `POST /savings/verify` | `200`, saved-plan outcomes with later usage evidence |
| `POST /cost` | `200`, estimated call, measured budget, verdict and scoped policy |
| Any other path or method | `404`, `error: "not-found"` with a detail string |

All responses are JSON with `Cache-Control: no-store`. No authentication or CORS
headers are added. The listener remains loopback-only; there is no configurable
network bind address. Do not expose it through a public reverse proxy.

## Discover integration capabilities

`GET /capabilities` returns `schemaVersion: 1`, `accessChannels`, `taskQuality`
and `harnesses`. It reads no files, environment variables, sessions or network
services. This is a support registry, not an installation detector.

| Harness ID | Native import | Normalized usage |
|---|---|---|
| `claude-code` | `from-claude-code`, Claude Code transcript JSONL | `bill` |
| `codex` | `from-codex`, Codex session JSONL | `bill` |
| `cursor` | `null`: no native importer | `bill` |
| `mcp-client` | `null`: no native importer | `bill` |

`accessChannels: ["cli", "mcp", "http"]` names Trazum entry points. It does not
claim that a harness automatically exposes, installs or calls all three.
`normalizedUsage` refers to the Trazum usage JSONL format; it is not a promise
that an arbitrary harness export is already compatible.

Every harness has `billingMode: "unknown"` and `automaticInterception: false`.
A harness name does not establish whether a user pays a subscription or API
charges. The gateway is opt-in, not an automatically installed hook. Likewise,
`taskQuality: "not-measured"` makes no cross-harness answer-quality claim.

The browser-safe core exports `HARNESS_CAPABILITIES` and
`getHarnessCapability(id)`. Lookup uses exact IDs and returns `null` for unknown
clients, rather than borrowing a different client's importer.

## Ask before a call

```sh
curl http://127.0.0.1:7317/cost \
  -H 'Content-Type: application/json' \
  --data '{"model":"claude-opus-5","inputTokens":1200,"outputTokens":300,"basis":"token-count","label":"synthetic-demo"}'
```

All fields are optional. An absent or whitespace-only body is `{}`. The body
must otherwise be a JSON object, at most **1,000,000 bytes**.

| Field | Accepted values | When omitted |
|---|---|---|
| `model` | String catalogue ID | No call estimate |
| `inputTokens`, `outputTokens` | Finite non-negative numbers; fractional counts remain accepted | Zero |
| `basis` | `token-count` or `heuristic` | `token-count` |
| `label`, `session` | Strings; an empty string means absent | No scope key |

Unknown properties are ignored. Invalid JSON, arrays, `null`, invalid field
types, negative/non-finite counts, unsupported `basis`, or oversized bodies
return `400` with `{ "error": "bad-request", "detail": "..." }`. The server
accepts JSON regardless of Content-Type for compatibility; clients should send
`application/json`. It does not accept raw prompt text or count tokens here.

## Interpret the answer

Every successful response contains `schemaVersion`, `call`, `budget`, `verdict`,
`restsOn`, `reason`, `afterCall`, and `policy`. The OpenAPI schema spells out
nullable fields and discriminated combinations.

- `call` is a catalogue-priced **estimate**, or `null` when absent/unpriced.
- `budget` is the **measured** position, or `null` without configured budget or
  measurement. Its window identifies the measured period; a snapshot is not a
  guarantee of live accounting.
- `verdict` is `within`, `over`, or `cannot-tell`. All three return HTTP `200`:
  transport success is not spending permission.
- `reason` distinguishes `no-budget-configured`, `nothing-measured`, and
  `model-unpriced`. It is `null` for a judged budget. `afterCall` carries the
  measured and estimated halves separately.
- `policy` independently judges day, session and label ceilings. `no-policy`
  means no applicable ceiling was judged; it does not grant unlimited budget.
  Inspect waivers and all judgements. Session identifiers are never echoed.

For fail-closed integration, require both the budget and applicable policy
judgements needed by your application to be acceptable. Do not turn unknown
measurements into zero, or treat an unknown model as free.

The endpoint evaluates snapshots supplied by the CLI. Concurrent callers can
receive the same answer; this API has no reservation ledger. See the
[gateway](gateway.md) for enforcement semantics and its limits.


## Plan and verify savings

`POST /savings/plan` takes `{ "log": "normalized JSONL text" }`.
`POST /savings/verify` takes `{ "log": "later normalized JSONL text", "plan": "serialized plan JSON" }`.
These endpoints receive text, never file paths. They do not read files, persist
plans, invoke models, reserve funds or access provider services. Import native
sessions first with `from-claude-code` or `from-codex` and retain their conversion
diagnostics separately. The HTTP endpoints cannot recover excluded source records.

Use the same server configuration for both requests. Its selected catalogue,
including any configured price overlay, prices all supplied logs. Request-level
pricing overrides are refused. `GET /openapi.json` is the runtime contract;
check it before using endpoints from a local development build with an older release.

This complete example uses synthetic normalized records and Node.js 20+:

```js
const base = 'http://127.0.0.1:7317';
const log = JSON.stringify({
  model: 'claude-opus-5', label: 'synthetic-work',
  usage: { input_tokens: 400000, output_tokens: 1000 },
});
async function post(path, payload) {
  const response = await fetch(base + path, {
    method: 'POST', headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(payload),
  });
  const result = await response.json();
  if (!response.ok) throw new Error(result.detail);
  return result;
}
const planned = await post('/savings/plan', { log });
const checked = await post('/savings/verify', {
  plan: JSON.stringify(planned.plan), log,
});
console.log(checked.verification, checked.evidence);
```

For real verification, replace the second `log` with later comparable usage.
Save only the response's `plan` field as a plan document; the complete response
also contains evidence and limitations worth retaining. The plan is compatible
with CLI `verify --against` and MCP `verify_savings`.

| Response field | Meaning |
|---|---|
| `schemaVersion` | `1` |
| `plan` or `verification` | The core plan document or verification result |
| `evidence` | Priced/unpriced calls, skipped line numbers, period and catalogue provenance |
| `limitations` | Assumptions and limits that the arithmetic cannot establish |

Projected savings and measured stakes remain separate. Verification retains
`arrived`, `not-arrived`, `cannot-tell`, attribution and gate failures. An arrived
action does not prove equal answer quality or net savings. A vanished workload
remains unknown. `evidence.complete` only means no unpriced calls or skipped
lines were detected; it does not prove complete billing or comparable periods.
Pricing review dates alone do not establish identical custom rates.

Both endpoints reject unknown request properties, missing/whitespace text,
invalid JSON, paths with no readable records and malformed nested plan fields.
Plan fields are validated defensively, including unknown properties. Empty or
entirely unreadable logs return `400 bad-request`; a log with recognized but
unpriced records returns `200` with explicit incomplete evidence and no invented
priced usage. Mixed malformed lines remain numbered evidence gaps.

The **1,000,000-byte** cap covers the entire UTF-8 request, including both text
fields and JSON escaping. Oversized bodies return `400`, not a partial result.
The `/cost` endpoint keeps its older permissive unknown-property behavior.
